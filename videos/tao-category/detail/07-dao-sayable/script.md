## 二 · 对象不可道　`02:09–03:36`

参考：DaoFP ch.1 Types and Functions；CTFP 1.1

| 时间 | 旁白 | 画面 / 代码 |
|---|---|---|
| 02:10 | 先立论点：在范畴里，对象是不可言说的。你不能指着一个对象说：看，这是我的元素。元素这个词，不在范畴的词典里。词典里只有关系。 | 论点大字；墨团对象 a |
| 02:25 | 对象没有部分。它不是集合论里的袋子，不能翻开、不能枚举、不能指着里面一粒一粒报数。它只是一个点——一个名字。集合论问「里面有什么」；范畴论问「通向哪里、从哪里来」。 | 淡墨晕染对象 a，无内部标签 |
| 02:43 | 这听起来很空。正是这份空，逼我们换一种认识方式：不靠打开，而靠探测。探测的工具，就是箭头。空不是虚无，是把内部让出来，好把关系写清楚。 | 书法小字：不靠打开 · 靠探测 |
| 03:00 | Haskell 程序员其实早有直觉：一个不导出构造子的抽象类型，模块外看不见内部。你对它的全部了解，只能来自那些以它为参数、或以它为结果的函数。 | 抽象类型 · 不导出构造子 |
| 03:16 | 对象不可道——不是说对象不存在，而是说：我们对它的全部可说之词，都不在它「里面」，而在它与别的对象之间的关系上。 | 可说之词在关系上 |
| 03:29 | 记住这句话。下一节，我们把话筒交给箭头。 | 过渡到箭头 |

## 三 · 箭头可道　`03:36–05:07`

参考：DaoFP ch.3 Isomorphism（Reasoning with Arrows）；CTFP 1.2

| 时间 | 旁白 | 画面 / 代码 |
|---|---|---|
| 03:37 | 能说出口的，只有箭头：射入它的箭头，从它射出的箭头，以及这些箭头怎样复合。对象的结构，是用箭头一下一下探测出来的。探测，就是言说。 | 箭头从四周射入、射出；复合 |
| 03:53 | DaoFP 第三章有一句几乎成了口号：Master Yoneda says: At the arrows look!——先别盯着对象，盯着箭头看。 | 书法/小字：At the arrows look! |
| 04:04 | 一支从 a 射向 x 的箭头，是对 a 的一种说法：它告诉你，在 x 的语境里，a 被怎样使用。换一个 x，就多一种说法。说法可以复合：先说 f，再说 g，等于一口气说 g 圆点 f。 | a → x 作为一种说法；复合 |
| 04:23 | 把所有可能的说法收在一起——对每一个 x，给一支 a 到 x 的箭头——你就得到「从 a 出发的全部可道」。Haskell 里，这正是续体风格的类型：Speak a。名字叫 Speak，正是「可道」二字的英文影子。 | forall x. (a → x) → x |
| 04:42 | 所以可以写成一句对仗：可道者，箭头也；不可道者，对象也。对象沉默；箭头替它说话。 | 书法对仗：可道者箭头也 |
| 04:54 | 但立刻有一个漏洞：若对象本身不可言说，我们凭什么断定两个对象相同？a 同构于 b，这句话的根据在哪里？ | 问号 a ≅ b ? |

## 四 · 自然性铺垫 / 米田一句　`05:07–06:29`

参考：DaoFP ch.3 / ch.9 Yoneda tease；CTFP 2.5–2.6（仅预告）

| 时间 | 旁白 | 画面 / 代码 |
|---|---|---|
| 05:07 | 漏洞不能假装没看见。范畴论的回答是：两个对象相同，不靠打开它们，而靠它们发出的箭头「一样」。相同，是外在的对齐，不是内在的剖视。 | 同构 = 箭头层面的对应 |
| 05:23 | 更精确一点：若从 a 出发的每一种说法，都唯一对应从 b 出发的同一种说法，并且这种对应还要在箭头合成时保持一致——这叫自然性。自然性，是「说法对齐」的纪律：你不能只对齐几个点，还要对齐路上的每一步。 | 自然性 = 说法对齐的纪律 |
| 05:44 | 米田引理会说：一个对象，被它出发的所有箭头完全刻画。对象不可道；但「它的全部说法」可道——而且恰好够用。DaoFP 里那句 Master Yoneda says，指的就是这件事。 | Yoneda 一句：对象被 Hom(a, −) 刻画 |
| 06:01 | 今天只点到这里。不写证明，不展开嵌入。先把钉子钉上：可道在箭头；同构在说法的对齐；米田，是后面赎回这句话的钥匙。 | 待进阶后集赎回 |
| 06:15 | 入门篇里，你已经见过函子保形、自然变换方块。那些方块，正是自然性的图示。进阶篇会一次次回到它们。 | 自然变换方块回响 |

| 时间 | 旁白 | 画面 / 代码 |

| 06:29 | 把刚才的话写成几行 Haskell。先做一个不导出构造子的类型 Dao：外界看不见内部，只能通过射入的 birth、射出的 speak 来认识它。 | 代码 s_dao；构造子不导出 |
| 06:43 | birth 把整数送进 Dao；speak 从 Dao 读出字符串。两支箭头，一进一出——这就是模块边界上全部可说的话。 | 高亮 birth / speak |
| 06:56 | 再写类型同义词 Speak a：对任意 x，吃一支 a 到 x 的箭头，交出一个 x。它收集「从 a 出发的一切说法」。这不是玄学，是类型里写出来的探测器。 | 代码 s_speak |
| 07:12 | hear 把一个具体的 a，变成它的说法：给你一支箭头 k，就把 a 喂给 k。这是续体传递的最小种子——后面米田会认出它。今天只要记住：值可以变成说法。 | hear :: a → Speak a |
| 07:28 | 跑一下：birth 四十二，再 speak，得到「道四十二」。hear 把四十二收成说法，再交给加一，得到四十三。图怎么说，代码就怎么应——不可道在类型边界，可道在函数签名。 | demo；边界 vs 签名 |

屏幕代码 `s_dao`（`haskell/src/DaoSayable.hs`）：

```haskell
-- 不可道：构造子不导出，外界看不见内部
newtype Dao = Dao Integer

birth :: Integer -> Dao        -- 射入 Dao 的箭头
birth = Dao

speak :: Dao -> String         -- 射出 Dao 的箭头
speak (Dao n) = "道" ++ show n
```

屏幕代码 `s_speak`（`haskell/src/DaoSayable.hs`）：

```haskell
-- 可道者：从 a 出发的一切说法（续体风格）
type Speak a = forall x. (a -> x) -> x
```

屏幕代码 `s_hear`（`haskell/src/DaoSayable.hs`）：

```haskell
-- 把一个值收成「它的全部说法」（米田侧的最小种子）
hear :: a -> Speak a
hear a k = k a
```

屏幕代码 `s_demo`（`haskell/src/DaoSayable.hs`）：

```haskell
-- 演示：边界上的箭头；说法喂给下一步
demoSpeak :: String
demoSpeak = speak (birth 42)           -- "道42"

demoHear :: Int
demoHear = hear (42 :: Int) (+ 1)      -- 43
```
