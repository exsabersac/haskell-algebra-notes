# 自由函子、自由代数与 Free 类型族

澄清「free functor / free algebra / free monoid / free monad」在函子层与对象层的关系，以及「挺多类型」的两种说法。  
术语保留精确英文：Functor、Free、cata、EM、End、UP（universal property）。

相关文档：[Fix编码.md](Fix编码.md) · [与自由代数和Monad.md](../初始代数/与自由代数和Monad.md) · [常见组合.md](../函子组合/常见组合.md) · [例子与Monad.md](../幺半范畴/例子与Monad.md)

---

## 1. 自由函子 vs 自由代数（同一故事，两层）

**自由函子**（free Functor）：相对遗忘函子的**左伴随**。  
例如遗忘 \(U : \mathbf{Mon} \to \mathbf{Set}\)，左伴随 \(F \dashv U\) 把集合送到自由 monoid；一般地，「生成自由代数对象」的那一步就是左伴随在对象上的取值。

**自由构造**（代数里常说的 free algebra）：给生成元集合 \(X\)，得到自由代数对象 \(F(X)\)，并带有 **UP**：任意从 \(X\) 到某代数载体的映射，唯一扩展为代数同态。

二者不是两套理论：

| 层次 | 说法 | 落点 |
|------|------|------|
| 函子层 | free Functor = 左伴随 | \(F : \mathcal{C} \to \mathbf{Alg}(\ldots)\) |
| 对象层 | free construction + UP | 对每个 \(X\)，\(F(X)\) 是自由代数对象 |

**\(F(X)\) 就是那次自由构造。** 说「free functor」时在谈伴随整条；说「free algebra on \(X\)」时在谈 \(F\) 在 \(X\) 上的值与 UP。

## 2. 自由 monoid 与自由 monad：同一模式，不同 ambient

二者是同一 **pattern**——「取自由代数／自由 monoid-对象」——但 ambient 幺半范畴不同；**不是**某一个固定 \(\mathrm{Alg}(F)\) 里的两个实例。

| | 自由 monoid | 自由 monad |
|--|-------------|------------|
| Ambient | \((\mathbf{Set},\times,1)\) | \((\mathrm{End}(\mathcal{C}),\circ,\mathrm{Id})\) |
| 输入 | 集合 \(X\) | 自函子 \(f : \mathcal{C}\to\mathcal{C}\) |
| 产物 | 自由 monoid（如列表） | 自由 monoid-对象 on \(f\)（即 free monad） |
| 另一视角 | list-functor 的初始代数 \(\mu Y.\,1 + X\times Y\) | 在 End 里对 \(f\)「自由加单位与乘法」 |

Sketch：

```haskell
-- Set 层：自由 monoid on X ≅ [X]
--   ≅ μ Y. 1 + X × Y

-- End 层：自由 monad on f
data Free f a = Pure a | Free (f (Free f a))
--   Free f  ≅  在 (End, ∘, Id) 里由 f 生成的自由 monoid-对象
```

记忆句：**同一「自由 monoid-对象」口号；张量从 \(\times\) 换成 \(\circ\)，输入从集合换成端函子。**  
详见 [例子与Monad.md](../幺半范畴/例子与Monad.md)。

## 3. 对象层：`Free f a ≅ μ ≅ Fix(Sum…)` 作为自由 \(f\)-代数

当 \(f\) 足够好、初始代数存在时，**固定生成元 \(a\)** 的那一棵树是：

```text
Free f a  ≡  μX. a + f X  ≡  Fix (Sum (Const a) f)
          ≡  由 a 生成的自由 f-代数（载体）
```

```haskell
-- 三种写法，同一载体（同构）
data Free f a = Pure a | Free (f (Free f a))

newtype Fix g = Fix (g (Fix g))
type FreeAsFix f a = Fix (Sum (Const a) f)   -- ≅ Free f a
```

- 载体上的代数结构由初始性／`cata`（或 `foldFree`）给出；UP 说：任意 \(f\)-代数 \(\varphi : f\,b\to b\) 配上对生成元的解释，唯一决定折叠。
- 编码细节与 `foldFree`≡`cata`：见 [Fix编码.md](Fix编码.md)。
- 与「无外部生成元」的 \(\mu f\) 对照：见 [与自由代数和Monad.md](../初始代数/与自由代数和Monad.md)。

## 4. 自由 monad = 整族，不是单个对象

**`Free f a`**：固定 \(f\) 与生成元类型 \(a\) 时的一棵（类）树 —— 一个自由 \(f\)-代数的载体。

**自由 monad `Free f`**：把 \(a \mapsto \mathrm{Free}\,f\,a\) 打成的整族，再配上 `Pure` / `join`（或 `>>=`），使 `Free f` 成为 End 里的 monoid 对象。

```haskell
pure  :: a -> Free f a                    -- η
join  :: Free f (Free f a) -> Free f a    -- μ
-- 单位与结合 ⇒ Monad (Free f)
```

所以：

```text
Free f a     =  某一个对象（自由 f-代数 on a）
Free f       =  整族 + Pure/join  =  自由 monad
```

不要把「自由 \(f\)-代数」和「自由 monad」当成同一个名词的两种拼写。

## 5. 「挺多类型」的两种意思

### （A）同一种自由 \(f\)-代数：多种编码

```text
Free f a  ≅  Fix (Sum (Const a) f)  ≅  μX. a + f X
```

写法不同，**载体同构**——这是编码同构，不是换了数学对象。

### （B）同一套 \(\mu/\nu\) 机器：换中间多项式 → 不同类型族

保留外壳 `Fix` / `Free` / `Cofree` / `Nu`，只换中间的 `Const` / `Sum` / `Product` / `Compose`（或公式里的 \(1+e\times Y\)、\(a+(f+g)Y\) 等），得到**不同的类型**：

```text
[] 、 NonEmpty 、 Free (f :+: g) 、 Fix ExprF 、 Stream …
```

这与 [常见组合.md](../函子组合/常见组合.md) 的「换中间式子 → 换含义」一致。

**不要混：**（A）是同一对象的多种写法；（B）是改公式造出另一族对象。

---

## 6. 已澄清结论 + 易混点

### 已澄清结论

1. Free Functor（左伴随）与代数里的 free construction（自由对象 + UP）是同一故事的函子层／对象层；\(F(X)\) 即自由构造。
2. 自由 monoid 与自由 monad 是同一 pattern，分别在 \((\mathbf{Set},\times,1)\) 与 \((\mathrm{End},\circ,\mathrm{Id})\)；不是固定 \(\mathrm{Alg}(F)\) 的两次取值。
3. 对象层：`Free f a ≡ μX. a + f X ≡ Fix (Sum (Const a) f)` ≡ 由 \(a\) 生成的自由 \(f\)-代数。
4. 自由 monad `Free f` = 整族 + `Pure`/`join`，不是单个 `Free f a`。
5. 「挺多类型」分编码同构与换公式的类型族两义；后者对齐函子组合笔记。

### 易混点

| 易混 | 澄清 |
|------|------|
| free Functor ≠ free object | 不说 ambient／伴随时，函子与对象会串；对象是 \(F(X)\)，函子是整条 \(F\) |
| 自由 \(F\)-代数 ≠ Free monad ≠ 自由 monoid | 分别是：固定生成元的代数对象；End 里的 monoid 对象族；Set 里的 monoid |
| EM 自由代数载体是 \(T X\) | 对一般 monad \(T\)，自由 EM 代数 on \(X\) 的载体是 \(T X\)（带 `join`），**不是**再写一遍 \(\mu Y.\,a + T Y\) |
| 多种编码 ≠ 换公式得到的不同类型 | 前者同构同一载体；后者换多项式／外壳得到新类型（见 §5） |
